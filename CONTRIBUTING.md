# Contributing

AG-UI.AI accepts corrections, source updates, translations, learning material, and carefully scoped product improvements.

## Before opening a pull request

1. Open or reference an Issue for claims that change technology positioning, maturity, source authority, or security guidance.
2. Prefer first-party specifications, official documentation, and upstream repositories. Label ecosystem interpretations explicitly.
3. Update English and Chinese files together, preserving slug parity.
4. Set `lastVerified` to the date on which you checked every listed source.
5. Do not paste project logos or substantial third-party prose. Use names, text labels, original explanations, and links.
6. Run all quality gates in the README.

## Technology profile requirements

Every profile must explain its layer, problem, selection and avoidance scenarios, composition patterns, maturity, security boundary, smallest useful example, source authority, official sources, and verification date.

Open-JSON-UI must remain described as an ecosystem-documented approach until an independent first-party specification can be verified.

## Pull request shape

Keep changes reviewable. Separate editorial changes from large visual or build-system changes. In the description, state:

- what decision or fact changed;
- which sources support it;
- which localized pages were updated;
- which checks passed;
- screenshots for visible UI changes.

By contributing, you agree that code is provided under MIT and original content under CC BY 4.0.
