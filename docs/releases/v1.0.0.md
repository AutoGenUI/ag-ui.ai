# AG-UI.AI v1.0.0 发布说明与验收条件

记录日期：2026-10-13。本文编写时为从 main `f670b23d32e6de1e4497f46113ef277fc3fc97cc` 继续的发布候选；用户已授权完成修复后正式发布并推送 tag。本文不预写尚未发生的合并 SHA、CI 或 Sites 部署成功。最终凭据见 GitHub 远端 tag、对应 PR/CI 和 [公开状态](../CURRENT_STATE.json)，接续前重新查询。

## 本版解决的问题

此前邮件里的“确认邮箱”按钮实际只打开页面，仍需页面主动确认；原申请标签页的容量也可能仍显示旧值。邮件测试身份可以确认成功，却按设计不占正式名额。三者容易被误解为确认失效，设备切换本身不会使签名失效。

- 中英 HTML/纯文本邮件明确“打开确认页 → 点击确认订阅 → 等待成功”，保留 24 小时有效期及可复制的原网址。
- 确认页突出最后一步按钮，成功后才提供偏好编辑；GET、预取或邮件扫描仍无确认/退订副作用。
- 返回原标签页的 focus/visibility 只刷新公开名额，防止容量停留在确认前结果。
- 订阅页切换中英文保留签名参数；离开该页不向其他页面传播参数。
- 签名响应区分 public/test，测试页明确不进入正式周报、不占名额；不自动将测试身份转正式。
- 保留容量原子控制、代际/epoch、防重复投递、unknown/uncertain 不自动重发、退订与抑制，以及现有生产配置与任务。

2026-10-13 用户报告用新邮箱完成公众确认后，页面已确认人数为 1。该报告说明公众确认路径有实际成功案例，不证明此候选已上线或取代完整验收；公开记录不保留邮箱、签名链接、邮件内容或订阅行。

## 发布前与发布后必须留下的证据

| 检查 | 验收条件 |
| --- | --- |
| 工程门槛 | 最新候选的测试、TypeScript、内容、lint、构建、链接和 required `verify`；保留 high 安全门槛及原 JS/CSS 预算，剩余告警准确记录 |
| 真实页面到本地 API | 隔离本地 D1、无真实密钥/投递；合成确认链接在另一浏览器上下文落地，GET 保持 pending，主动确认后正式计数 `0→1`、名额 `250→249`，重放不重复计数 |
| 测试与异常边界 | test 确认始终不占正式名额并显示测试身份；坏签名、到期、满额、代际更新、退订/抑制及未知提交不产生虚假成功或重发 |
| 页面交互 | 桌面/手机双语确认、签名页语言切换、原标签页重新聚焦刷新、偏好与退订；旧 API 缺少身份字段显示保守错误，刷新匹配版本后恢复 |
| GitHub | 经必需检查正常合入 main，远端 `v1.0.0` 指向已验证的 release commit；记录 PR、CI 和 tag 解析结果，不改写已有 tag |
| Sites | 原项目、原域名、公开权限、DB 与安全配置保持；记录真实 source commit、数字版本 ID、deployment ID/最终状态，以及 GitHub SHA 对应关系 |
| 上线验证 | 查询部署最终成功后，检查双语页面、RSS、公开容量、匿名管理隔离和网络边界；不将首页 200 当作数据库、真人投递或全球可访问性证明 |

本地 mock 与用户既有反馈不能补成新增真实周报、退信或 webhook 验收。发布检查不主动申请订阅、drain、mail-test 或伪造 Delivered；需要额外真实投递时按 owner 明确授权和 [邮件维护](../operations/email-subscriptions.md) 执行。

## 版本与接续

GitHub 远端 `v1.0.0` tag 是本版源码的正式权威标识；`package.json` 的版本号只是工程元数据。可在 [仓库 tags](https://github.com/AutoGenUI/ag-ui.ai/tags) 查询，或只读执行：

```sh
git ls-remote --tags origin 'refs/tags/v1.0.0' 'refs/tags/v1.0.0^{}'
```

带注释 tag 的原始 tag 对象 SHA 与解析后的 commit SHA不同，记录 release commit 时用解析结果。tag 还未创建时没有输出，不能因此假设已发布。

Sites 的数字版本序号由平台生成，与语义版本独立；v1.0.0 不意味着 Sites version 1。使用原项目的 `get_site` 和对应 `get_deployment_status` 查询实际部署；保存版本不等于部署成功，GitHub push 也不等于上线。完整步骤见 [部署维护](../operations/deployment-maintenance.md)。

本版不迁移 schema。新客户端要求签名响应中的身份字段，回退时必须恢复匹配的客户端/Worker并刷新页面；混合版本报错不代表确认事务未执行，不重复发信或修改 `is_test` 来消除提示。日常接手先核对实际远端、工作区、Sites 版本、运行状态和授权范围，继续以 main 迭代，保留公开 [维护手册](../operations/README.md) 与私有配置的边界。
